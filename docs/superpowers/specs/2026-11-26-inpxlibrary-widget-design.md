# Віджет `inpxlibrary`: лічильники, індексація, «читаю», «хочу прочитати», полиця

Дата: 2026-11-26. Статус: **чернетка, чекає схвалення автора**. Джерело: [Habsaec/inpx-library-server](https://github.com/Habsaec/inpx-library-server) (MIT, Node.js/Express/SQLite).

## Навіщо

Автор має власний сервер книжкової бібліотеки (INPX) і хоче бачити на дашборді: розмір бібліотеки, стан індексації, а також особисте — що він читає, що хоче прочитати і останні книги з однієї своєї полиці.

## Цілі

1. Блоки лічильників: книги, автори, серії, жанри, мови (поля вибираються через `fields`, як в інших віджетів).
2. Стан індексації: «Індексується X / Y архівів», а коли не йде — дата останньої індексації.
3. Три розділи-акордіони, **вимкнені за замовчуванням**, лише з логіном: «Читаю», «Хочу прочитати», «Полиця: <назва>» — до 10 книг, кожна з обкладинкою (за можливості), назвою, автором, посиланням.
4. Опції, документація, тести, каталог редактора.

## Не цілі

- Без адмінських даних (потрібна сесія адміністратора; Basic там не працює).
- Без керування сервером (перезапуск індексації тощо) і без змін у бібліотеці.
- Без проксі для обкладинок (див. «Мої рішення»).
- Без Prometheus/метрик (на сервері їх немає).

## Анти-цілі

- Витік пароля чи ключа в браузер.
- Блокування облікового запису автора сервером через неправильний пароль (сервер обмежує перебір паролів Basic) — віджет не повинен слати запити з порожнім або явно хибним логіном.
- Падіння віджета, коли книга без обкладинки/серії, або коли сервер недоступний.

## Перевірені факти про API (вихідний код, гілка `master`, 2026-11-26)

- `GET /api/index-status` — **публічний**: `{...getIndexStatus(), stats, port}`. `stats` = `{totalBooks, totalAuthors, totalSeries, totalGenres, totalLanguages}` (кешується сервером, TTL ~10 хв). Поля індексації: `active`, `ready`, `indexedAt`, `processedArchives`, `totalArchives`, `importedBooks`, `uniqueBooks`, `newBooksCount`, `currentArchive`, `currentStage`, `paused`, `error`.
- `GET /health` — публічний: `{ok, service, version, time, port}` (або лише `{ok:true}` при `healthMinimal`). `GET /ready` — публічний, 503 якщо не готовий.
- `GET /api/library/continue` («читаю») і `GET /api/library/want` («хочу прочитати`) — відповідь `{items, total, page, pageSize}`; query `page`, `pageSize`(для цих двох до 500). Елемент (з`mapBookListRow`): `id`, `title`, `authors`, `genres`, `series`, `seriesNo`, `ext`, `lang`, `authorsList`, `downloadFormats`, `coverColor`.
- `GET /api/shelves` — масив полиць користувача (порядок користувача); `GET /api/shelves/:id/books` — книги полиці, `ORDER BY added_at DESC` (тобто «10 останніх» — перші 10); поля `id, title, authors, genres, series, seriesNo, ext, lang, archiveName, addedAt`. Обидва лише з Basic (`requireApiAuth`).
- Автентифікація особистих маршрутів — **HTTP Basic з обліковими даними користувача**; `/api/library/*` (`requireBrowseAuth`) приймає Basic або анонімний перегляд, якщо його ввімкнув адмін.
- Сервер перевіряє Basic на будь-якому URL і має ліміт невдалих спроб (`isRateLimited`).
- Обкладинка: `GET /api/books/:id/cover-thumb` (`requireBrowseOrOpds`: сесія або анонімний перегляд; Basic тут не використовується). Сторінка книги: `/book/:id`.
- Не знайдено: Prometheus, лічильники завантажень, публічний список користувачів.

## Підходи

- **А. Новий віджет `inpxlibrary`** за зразком Jellyfin (обрано автором): власний `widget.js` з `mappings` і проксі з Basic-автентифікацією, `component.jsx`, `library`-подібний підкомпонент для акордіонів.
- **Б. `customapi`** — не вміє акордіони, обкладинки й кілька запитів. Відхилено.
- Полиця: **А** — одна полиця за назвою (`shelf: "Назва"`); **Б** — усі полиці окремими акордіонами. Обрано автором **А**.

## Рішення автора

- Новий віджет; полиця вибирається **назвою в конфізі**; «читаю» = `continue`, «хочу прочитати» = `want`; до 10 книг.

## Мої рішення (їх можна виправити)

1. **Автентифікація:** поля `username` і `password` у конфізі віджета; проксі шле `Authorization: Basic …` з сервера Homepage. Пароль ніколи не йде в браузер. Без `username` розділи з паролем не показуються й жодних запитів до особистих маршрутів не робиться.
2. **Обкладинки:** без проксі — браузер завантажує `{href}/api/books/{id}/cover-thumb` напряму. Працює, якщо в бібліотеці ввімкнено анонімний перегляд або браузер має сесію в бібліотеці; інакше зображення ховається (`onError`), лишається текст. Проксі для зображень свідомо не робимо (Basic не підходить для `cover-thumb`, а бінарний проксі — окремий обсяг).
3. **Лічильники й індексація** беруться з публічного `/api/index-status`, тож `username` для них не потрібен.
4. **Полиця:** шукаємо за назвою без урахування регістра; якщо не знайдена — підказка «полицю не знайдено». Якщо `shelf` не задано, розділ полиці не показується.
5. **Індексація:** рядок із прогресом показується лише при `active: true`; інакше — «оновлено <дата>» з `indexedAt`.
6. **Ліміт:** `count` 1–10, за замовчуванням 10; для `continue`/`want` просимо `pageSize=count`.
7. **Не блокувати обліковий запис:** після відповіді 401 віджет припиняє повторні запити з тими самими даними (показує помилку), щоб не множити невдалі спроби.

## Опції віджета

| Опція                  | За замовчуванням                        | Значення                                                       |
| ---------------------- | --------------------------------------- | -------------------------------------------------------------- |
| `fields`               | `["books","authors","series","genres"]` | дозволені: `books`, `authors`, `series`, `genres`, `languages` |
| `username`, `password` | —                                       | облікові дані користувача бібліотеки (для розділів нижче)      |
| `showReading`          | `false`                                 | «читаю» (`continue`)                                           |
| `showWant`             | `false`                                 | «хочу прочитати» (`want`)                                      |
| `shelf`                | —                                       | назва полиці, показати її останні книги                        |
| `count`                | `10`                                    | книг у кожному списку (1–10)                                   |
| `showIndexing`         | `true`                                  | рядок про індексацію/дату оновлення                            |
| `expandSections`       | `false`                                 | відкрити акордіони                                             |

## Що лишається виконавцю

- Реалізація за окремим планом (після схвалення): `src/widgets/inpxlibrary/{widget.js,proxy.js,component.jsx,…}`, реєстрація в `widgets/widgets.js` і `widgets/components.js`, передача нових опцій через `cleanServiceGroups`, переклади, `docs/widgets/services/inpxlibrary.md`, `mkdocs.yml`, каталог редактора.
- Звірити з існуючим credentialed-проксі Homepage (`utils/proxy/handlers/credentialed.js` чи Basic-аналог) перш ніж писати власний.
- Тести на фікстурах відповідей сервера.

## Перевірка

Юніт-тести проксі та компонента на фікстурах (форми відповідей взято з вихідного коду). На живому сервері бібліотеки віджет **не перевірявся** — це робить автор.
